# Workspace Operating Instructions

These instructions apply to every agent and every task in this workspace.

## Current-authority preflight

Before planning, drafting, editing, reviewing, or implementing work in this tree,
read the root `AGENTS.md` and `CLAUDE.md`, then consult the current owner document
for the facts or architecture the task touches. Use
[`BRAND_MEMORY.md`](./BRAND_MEMORY.md) selectively for relevant post-reset
decisions, approval history, and rejection evidence. During the voice reset it is
an archival record, not a creative brief, and must not be read wholesale as one.

For brand, marketing, sales, advertising, campaign, social, email, website,
SEO, creative, audience, offer, or customer-facing work:

1. Start with the user's latest direction and the binding voice-reset rules.
2. Read only the memory sections and decisions relevant to the named surface;
   `[UNKNOWN]`, `[TESTING]`, and archival framework fields are not requirements.
3. Verify operational, clinical, pricing, provider, NAP, compliance, and route
   facts against their current owner documents.
4. Mark unresolved information as unresolved instead of completing a framework
   with assumptions.

If the memory and the user's latest explicit instruction conflict, follow the
user. If two stored facts conflict, follow the source-priority rules in
`CLAUDE.md` and the memory, and surface a material unresolved business decision
instead of quietly choosing a side.

## Selective decision write-back

Update `BRAND_MEMORY.md` only when the work reveals or creates durable,
cross-task information, including:

- a confirmed brand, audience, offer, voice, or channel decision;
- an approved or rejected phrase, message, claim, or creative direction;
- new proof, customer language, research, or campaign performance;
- a contradiction, constraint, compliance rule, or unresolved question;
- a reusable lesson likely to improve future work.

Do not write back routine implementation details, source corrections already
owned elsewhere, brainstorms, disposable drafts, generic advice, or unsupported
assumptions. Label new entries using the evidence states defined in the memory.
When a memory update is warranted, update `Last updated` and append a short entry
to the Change Log.

Never silently overwrite an established decision. Mark it superseded, explain
why, and link the replacement decision.

## Delivery requirements

Every customer-facing deliverable must be traceable to current user direction,
verified facts, and applicable compliance and architecture rules. Use the Brand
Alignment Gate only for the relevant, currently decided items; do not force a
deliverable through its blank audience, offer, funnel, or voice framework.

When the memory lacks essential context, make the smallest safe assumption,
label it `[INFERRED]`, and keep claims conservative. Ask the user only when the
missing information would materially change the result or create brand, legal,
financial, or reputational risk.
