## 1. How to use this memory

This file is a decision system, not a scrapbook. It should help an agent answer:

- Who are we speaking to, and what is happening in their world?
- What outcome do they want, what blocks them, and what do they already believe?
- What does the brand promise, and why should someone believe it?
- Which offer, message, proof, and call to action fit this stage and channel?
- What must the copy sound like—and what must it never sound like?
- What has already been tried, approved, rejected, or learned?
- How does each fact affect downstream creative decisions?

### Evidence states

Every substantive addition should carry one of these labels:

- `[VERIFIED]` — supported by an authoritative source or confirmed by the user.
- `[DECIDED]` — an explicit strategic or creative choice currently in force.
- `[OBSERVED]` — directly present in customer language, research, or results.
- `[INFERRED]` — a reasonable working interpretation that still needs validation.
- `[TESTING]` — an active hypothesis being tested.
- `[SUPERSEDED]` — retained for history but no longer governing current work.
- `[UNKNOWN]` — important information that has not been supplied or established.

Never promote an inference to a fact without evidence. Never place an
unverified product, performance, health, financial, scarcity, testimonial, or
comparative claim in published copy.

### Source priority

When sources disagree, use this order unless the user explicitly directs
otherwise:

1. The user's latest explicit instruction or approval.
2. Current legal, compliance, product, pricing, and operational documentation.
3. Verified customer research and measured campaign results.
4. Current approved brand strategy and guidelines.
5. Previously approved copy.
6. Agent inference.

Record meaningful conflicts in Section 16 instead of quietly choosing a side.

### What belongs here

Keep durable information that will improve multiple future tasks: governing
decisions, proof, patterns, constraints, approved language, performance lessons,
and the reasoning that connects them.

Do not store passwords, API keys, private customer data, regulated personal
information, raw transcript dumps, or every version of a draft. Link to source
material when it exists and summarize only what is reusable.

### Recommended ad logic

Use the lightest structure that makes the case:

1. **Hook:** Name a relevant tension, desire, contrast, or specific truth.
2. **Bridge:** Connect that truth to the brand's worldview or mechanism.
3. **Value:** Make the outcome concrete and audience-relevant.
4. **Proof:** Supply the most credible evidence available for this stage.
5. **Offer:** State what the person gets and reduce ambiguity.
6. **CTA:** Ask for one proportionate next step.

The structure is not a fixed formula. Awareness stage, placement, and creative
format determine how many elements belong in one ad.

### Copy QA for ads

An ad is not ready until all applicable answers are “yes”:

- Does the hook come from a real audience tension or desire?
- Is the intended audience able to recognize themselves without stereotyping?
- Is the promise consistent with the offer and operational reality?
- Is every claim supported in the claim ledger?
- Is the differentiator meaningful rather than merely decorative?
- Does proof appear before the audience must make a high-trust decision?
- Does the copy match the audience's awareness state?
- Is the CTA a natural next step rather than a leap?
- Does it sound like the voice system in Section 10?
- Does it avoid false urgency, shame, fear exploitation, and generic hype?
- Does it match the landing experience in message, offer, and tone?
- Is the test variable clear enough to produce a reusable learning?

## 17. Brand Alignment Gate

Run this gate before delivering any brand-affecting work. A material “no” must
be fixed, explicitly disclosed, or logged as an unresolved risk.

### Strategy

- [ ] The audience and their current situation are clear.
- [ ] The work serves a defined objective and awareness stage.
- [ ] The selected message, offer, and CTA form one coherent path.
- [ ] The deliverable expresses a meaningful brand difference.

### Truth and trust

- [ ] Claims are present in the claim ledger or conservatively qualified.
- [ ] Proof is real, relevant, and used in the right context.
- [ ] The work does not invent urgency, scarcity, testimonials, or outcomes.

## 18. Update protocol

### Before the task

1. Read this file completely.
2. Pull the relevant audience, offer, message, proof, voice, channel, and history.
3. Identify unknowns and contradictions.
4. Build the brief from stored truth; do not force the truth to fit a favorite idea.

### During the task

1. Keep facts, decisions, observations, inferences, and tests distinct.
2. Trace recommendations through the Connected-dots Strategy Map.
3. Check claims before using them.
4. Preserve useful customer language and evidence provenance.

### After the task

1. Run the Brand Alignment Gate.
2. Write back only durable knowledge.
3. Update affected sections rather than duplicating the same fact elsewhere.
4. Add a Decision Ledger entry for consequential choices.
5. Add a Change Log entry with the date, sections changed, reason, and source.
6. Update `Last updated`; increment the memory version for meaningful structural
   or strategic changes.

### Version convention

- Patch (`1.0.1`): wording, source, clarification, or small learning.
- Minor (`1.1.0`): new confirmed strategy, offer, audience, voice, or campaign layer.
- Major (`2.0.0`): foundational repositioning or incompatible brand direction.

### Anti-regression rule

Before changing an established choice, locate its Decision Ledger entry and
source. If the change is legitimate, mark the old entry `[SUPERSEDED]`, add the
replacement, and document downstream sections that need updating. Never erase
the reasoning trail merely to make the file look tidy.
